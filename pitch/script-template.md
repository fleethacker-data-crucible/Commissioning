# Script template: knowns locked, tool slots left open

I'm not choosing the showcase tools. This script is built so that picking them is a last-minute fill-in. Everything outside the slots does not change with the choice.

## 1. What is locked (does not depend on which tools you pick)

**Opening scene** (see `full-script.md`): the Captain's order is "Then we work with what's aboard. Raise Periscope." and DELGADO's answer is "Aye, Captain! Periscope is up. SCOPE online!" Neither names a tool, so the reshoot does not wait on the decision.

**Tour intro:** "SCOPE is a home for tools. This is Periscope."

**Tour outro (the number fills itself in):** "All of them hosted in SCOPE. {N} shown, sixteen in all. No admin. No install."

**Close card:** "Edge Ops. Any tool you want, built to one standard. Deploy in a click. Give us a sponsor and an ISSM, and we'll take it to authority to operate." Footer: "Team project. Not a US Navy product. Not endorsed by the Navy. Demos use synthetic data." Never claim an existing ATO.

## 2. The slots

| Slot | What goes in it | Where it is set |

## 3. How the tour handles the other tools

One pass, top to bottom. A featured tool gets its full spoken line (about 5 s) and a ring around its card. Every other tool is **just named, in under a second**, while its card scrolls past with its one-line tagline on screen. All 16 are covered, so the audience sees how many there are without hearing a pitch for each.

Example for FEATURED = gangplank, capstan (generated by the page; open `index.html#script&feature=gangplank,capstan` to print the exact words and times for any set):

> SCOPE is a home for tools. This is Periscope. SnapShackle. Bowerbird. **Capstan records your screen and edits the video.** Halyard. **Gangplank puts people on Git projects without Git training.** PacketRat. Shellback. Eight Bells. Semaphore. Data Noodler. Fairlead. Windlass. Phoenix LAI. Scrimshaw. TalkForge. Lazarette. All of them hosted in SCOPE. Two shown, sixteen in all. No admin. No install.

About 25 to 35 s depending on how many are featured. Record the printed script in one pass as `interactive/intro-vo.mp3`, then nudge any line with `TIME_OVERRIDES` (seconds, by tool id).

## 4. Demo narration template (one per featured tool)

Signal-Gun already holds a `DEMO.md` spec for 15 of the 16 tools (all except Data Noodler), with `one_line`, `key_flows`, `highlight` and `skip`. Fill the slots from the spec, in this fixed shape. About 80 to 90 s.

> **[intro]** {TOOL} {one_line, shortened to one sentence}.
> **[flow 1]** {key_flow 1, one sentence, present tense}.
> **[flow 2]** {key_flow 2}.
> **[flow 3]** {key_flow 3}.
> **[flow 4, if any]** {key_flow 4}.
> **[highlight]** {highlight line: the one thing you want them to remember}.
> **[close]** {TOOL}. {one short tagline}. All data shown is synthetic.

Rules:
- One narrator voice for every demo.
- Do not narrate anything the screen does not show. Where a spec says the demo is a synthetic fixture (Fairlead) or slow by design (Windlass), say so in one line.
- Say only what the spec's `key_flows` support. Skip what the spec's `skip` list excludes.
- `generate.ps1` can draft a first pass from the spec; edit it by hand.
- Then: `render.ps1 -Stage plan`, `import-voice.mjs --export`, generate the clips, `import-voice.mjs --clips`, then capture and compose (see `Signal-Gun/docs/RENDER.md`).

How to read it:
- "network" means the catalog says the tool needs a network connection; "Outlook" means it needs Outlook on the machine; "GPU" means it needs a GPU. A live demo on a machine without those can fail. Check the demo machine.
- Status is the catalog's word. Say "working prototype" for anything below beta.
- No spec means Signal-Gun cannot generate that tool's demo from a spec. Data Noodler needs a spec written first.

Questions to answer before you fill FEATURED:
1. Which tool does the audience in the room feel in their own work? (Developers, watchstanders, data analysts, leadership.)
2. Which one runs cleanly on the machine you will present from, with the network off?
3. Which has a rendered demo video, or can have one in time?
4. Which covers different needs from the others, so the three show range?

## 6. Last-minute procedure

1. Pick the tools. Set `FEATURED` (or use the URL form).
2. Open `index.html#script` and record the printed script.
3. Render and voice the demos for the featured tools. The others show "This demo has not been rendered yet" until you do them.
4. Adjust `TIME_OVERRIDES` to the recording.
5. Check the close card line and the on-screen footer.
6. Watch the whole thing once with the sound off, once with it on.
